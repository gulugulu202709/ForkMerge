# 视频到达后的接入与执行

本说明针对待录制的日常视频原型；已有螺丝仿真结果复算另见experiments/screw_repair/README.md。本次交接整理没有启动GPU。原始录像放在仓库根目录incoming/，机器可读标注为incoming/manifest.json；不改动/裁剪原片。CPU接入可本地运行，原生训练仍需Linux与真实预算记录。

## 我们负责补齐的实际标注

录制者只需保留原片和记录表。由本任务根据原片补充机器可读标注：历史截止、四个历史阶段、左右稳定揭示窗口、左右区域框、实际颜色/数量和已核验的操作/机位。录制脚本的预期不能填成真值。看不清的条目标为不可判，不训练。

recording/pipeline_annotations_template.json 是待填模板，不是数据；其中时间、区域、实际读数为空，所有核验项为false，因此无法放行。

复核会给出左右读出位置、时间窗、类型和固定问题，不按单条视频答案临时生成选项：换杯左侧只问“是否有可见液体”（empty空／nonempty有液体），右侧只问“是否有可见洒落痕迹”（clean无／marked有，不推断是否仍然潮湿）；茶壶左右都问“液体颜色”（clear无色液体／各色／other其他，空容器不能回答成无色液体）；糖盒两侧只填写非负整数数量。共享词表提前固定，每条仅显示对应问题的有效选项。看不清或无法回答指定属性时标unknown，保留未决，不强行记成状态错误。两组顺序可能被操作者知道，因此这里只称去标识复核，不声称独立双盲。

## 放行顺序

1. `python -m pipeline.entry prepare`：CPU解码、按时间截断历史、防止未来帧泄漏，检查原片/录制ID和划分不重叠。9条只进入calibration；正式数据另需train/dev/test各场景至少一个3条单元，最低27条正式片。只按这个最小数录制也不代表统计证据充分。
2. `python -m pipeline.entry calibrate`：固定读数器与实际校准结果核对。空杯透明度和不可靠自动读数明确走人工观察；自动读数失败不会悄悄切换成成功。实际标注必须形成要检验的擦除/保护关系，否则停止。
3. `python -m pipeline.entry run --phase diagnostics`：只有前两步通过才运行3段有真实终点条件的渲染诊断；这是接口上限检查，不能当作方法预测。运行后退出释放GPU，等待去标识复核。
4. `python -m pipeline.entry review --phase diagnostics`：复核者在pipeline_state/reviews/diagnostics/answers.json填写实际观察；模板隐藏方法名和正确答案，保留每条样本。检查动作、镜头、左右曝光及实际读数。未判清不能通过。
5. 正式数据到齐后再prepare；允许在既有校准数据完全不变的条件下补充一次正式数据。`run --phase cache`冻结数据并建立两组共享的历史特征；测试未来不编码为生成器条件。
6. `run --phase paired`训练普通更新器＋原配对监督，并保存测试视频和实际记忆张量。`review --phase paired`完成相同去标识复核。样本全对就停止候选新监督；训练不足或曝光不可判则未决。
7. 仅在普通组达到训练检查、全部样本已读且有错误时，`run --phase paired_worst_witness`才会放行；同一数据/种子/训练与采样设置。随后同样复核，比较实际状态结果。

所有命令在本轮目录、既有Python环境内执行。各GPU阶段都是一次性有上限调用，不自动排队、切换设备、重试或等人时占卡。原预算包含前次193.3471秒；不增加总额度。预算不足留下明确未完成样本，不换种子或降低设置补结果。

## 准备完成仍未验证的部分

CPU自测使用临时SELFTEST数据，能查接口和拒绝逻辑；不能证明实拍片可读、颜色计数已校准，或这三例的原生生成/反向训练已运行。实际记忆差分只作描述，不能单凭热图声称学会擦除/保护。
